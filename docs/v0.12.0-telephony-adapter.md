# v0.12.0 Telephony Adapter Baseline

## 목표

웹 자동 음성상담 엔진과 실제 전화망 사이에 사업자 중립 어댑터 계층을 둔다. Twilio, SIP/Asterisk, 국내 CPaaS 등 특정 사업자의 WebSocket/코덱/이벤트 형식이 RAG/STT 핵심 엔진에 직접 침투하지 않도록 한다.

## 내부 표준 계약

- 내부 오디오 표준: `pcm_s16le`, 16 kHz, mono
- 인바운드 이벤트
  - `call.started`
  - `audio.inbound`
  - `dtmf.received`
  - `call.stopped`
- 아웃바운드 명령
  - `audio.outbound`
  - `audio.clear`
  - `call.handoff`
  - `call.hangup`

실제 사업자 어댑터는 사업자 고유 이벤트를 위 계약으로 변환하고, 내부 명령을 사업자 고유 메시지로 인코딩한다.

## 책임 분리

1. Telephony Provider Adapter
   - 전화 수신/종료 이벤트 변환
   - 오디오 코덱 변환
   - DTMF 변환
   - 담당자 전환/통화 종료 명령 변환
2. Conversation Engine
   - VAD/턴 제어
   - STT
   - 승인근거 RAG
   - AI 답변
   - handoff 정책
3. Server TTS Adapter
   - 전화망으로 보낼 음성 생성
   - 사업자 요구 코덱으로 변환

Browser TTS는 웹 시연용이며 전화망 송출용 TTS가 아니다.

## v0.12.0 범위

- provider-neutral TypeScript contract
- simulator adapter
- `/api/telephony-adapter` contract inspection/validation endpoint
- UI 통화 시뮬레이터
- call start / inbound audio / outbound audio / handoff / stop 흐름 검증

## 비범위

- 실제 PSTN 번호 구매
- 실제 SIP trunk 연결
- 장시간 WebSocket media gateway 운영
- server TTS 선택
- 실제 개인정보/민원 통화
- 자동처분/자동발송

## 배포 원칙

Vercel Serverless를 장시간 양방향 전화 미디어 WebSocket의 최종 호스트로 전제하지 않는다. 실제 전화망 연결 단계에서는 지속 연결을 안정적으로 유지할 수 있는 별도 media gateway 런타임을 두고, 기존 Vercel 앱은 관리 UI/API 및 기존 RAG 서비스 역할을 유지하는 구조를 우선 검토한다.
