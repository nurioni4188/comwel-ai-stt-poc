# v0.15.0 Live Telephony E2E Baseline

## 완료 정의

실제 시험 전화 한 통에서 아래 전체 경로를 통과해야 v0.15.0을 병합/태그한다.

1. 검증된 시험 휴대전화 → Twilio Trial Voice 번호/시험경로
2. Twilio `<Connect><Stream>` → 공개 WSS Media Gateway
3. Twilio `audio/x-mulaw`, 8 kHz mono → Gateway PCM16/16 kHz 변환
4. 8초 메모리 발화 버퍼 → WAV
5. shared-secret으로 보호된 기존 `/api/telephony-adapter` → STT ingest
6. 같은 보호 adapter → 승인근거 RAG answer
7. OpenAI `/v1/audio/speech` Server TTS
8. PCM → μ-law/8 kHz 변환
9. Twilio `media` + `mark` → 수화기에서 AI 음성 청취
10. 다음 발화 1회 또는 근거부족 fallback 확인

## 현재 자동 구현 완료

- `gateway/liveBridge.mjs`
- 전화 오디오 8초 메모리 버퍼링과 WAV framing
- 한 실전화 통화에 하나의 STT session UUID, turn별 연속 `chunkIndex`
- 8초 경계 초과 PCM remainder를 다음 turn 버퍼로 보존
- 기존 `api/telephony-adapter.ts` 안에 Gateway 전용 `gatewayOperation` multiplex 추가
- `stt_ingest`, `rag_answer`, `session_complete` 세 작업을 한 기존 Vercel Function에서 처리
- Gateway → Vercel 요청에 `x-stt-internal-token` shared-secret 인증 적용
- 토큰 비교에 `timingSafeEqual` 사용, 미설정 503, 불일치 401
- Vercel Hobby 12 Serverless Functions 제한을 넘기지 않도록 별도 Gateway API Function을 추가하지 않음
- adapter 내부 upstream host는 요청 Host가 아니라 신뢰된 `VERCEL_URL`만 사용
- 통화/소켓 종료 시 in-flight turn 종료 후 session-complete best-effort 호출
- 승인근거 답변 → Server TTS → Twilio 송출
- OpenAI Server TTS 24 kHz / 16-bit / mono PCM 계약 + timeout
- 근거 부족 → 담당자 확인 안내 후 live loop stop
- TTS 생성/재생 중 inbound audio 무시, Twilio `mark` 후 다음 청취 재개
- STT/RAG HTTP timeout
- Twilio start media format μ-law/8 kHz/mono 검증
- Twilio WebSocket 서명 검증
- `/v1/sessions`, `/v1/tts`, `/v1/clear`는 `GATEWAY_CONTROL_TOKEN`으로 보호
- Gateway 원시 통화 오디오 파일/DB 저장 없음

## 데이터 보존 주의

보호된 adapter의 `stt_ingest` 작업은 내부적으로 기존 `/api/stt-ingest`를 호출하므로 **인식된 STT 텍스트는 `stt_poc` transcript 테이블에 저장**된다. 따라서 v0.15 실전화 시험에는 실제 민원인 개인정보나 실제 사건 내용을 사용하지 않고 아래 비식별 합성 시험문장만 사용한다.

- Gateway는 원시 통화 오디오 파일을 저장하지 않는다.
- Gateway 메모리 발화 버퍼는 turn 처리 후 폐기한다.
- STT 인식문과 세션 상태는 기존 STT PoC 저장정책을 따른다.
- 실제 민원·개인정보 연결 전에는 개인정보·보존기간·접근통제 검토가 별도로 필요하다.

## Gateway 필수 환경변수

```text
TELEPHONY_PROVIDER=twilio
LIVE_E2E_ENABLED=true
TWILIO_AUTH_TOKEN=<Twilio Console 값>
PUBLIC_MEDIA_WSS_URL=wss://<gateway-host>/v1/media
OPENAI_API_KEY=<existing OpenAI API key>
OPENAI_TTS_TIMEOUT_MS=30000
AI_APP_BASE_URL=https://<v0.15-tested-vercel-host>
STT_INTERNAL_API_TOKEN=<Vercel과 Railway에 동일하게 설정할 강한 난수 secret>
GATEWAY_CONTROL_TOKEN=<Gateway 제어면용 별도 난수 secret>
LIVE_TURN_MS=8000
LIVE_HTTP_TIMEOUT_MS=20000
```

`STT_INTERNAL_API_TOKEN`과 `GATEWAY_CONTROL_TOKEN`은 서로 다른 값을 사용하고 GitHub/문서/로그에 실제 값을 기록하지 않는다. `AI_APP_BASE_URL`은 실전화 전에 v0.15 보호 adapter가 실제 배포된 Vercel host로 고정한다.

## Gateway → Vercel 보호 경로

실전화 Gateway는 다음 단일 endpoint만 호출한다.

```text
POST /api/telephony-adapter
x-stt-internal-token: <STT_INTERNAL_API_TOKEN>
```

요청 body의 `gatewayOperation`은 다음 세 값만 허용한다.

- `stt_ingest`
- `rag_answer`
- `session_complete`

adapter가 각 operation을 기존 STT/RAG endpoint로 서버 내부 전달한다. 허용되지 않은 operation은 400, 토큰 미설정은 503, 잘못된 토큰은 401이다.

### 기존 브라우저 PoC와의 관계

기존 브라우저 PoC가 직접 사용하는 `/api/stt-ingest`, `/api/stt-session-complete` 등의 동작은 v0.15에서 깨뜨리지 않는다. **실전화 Gateway만 인증된 adapter 경로를 사용한다.**

따라서 이번 보강은 실전화 서버 간 경로를 보호하는 조치이며, 기존 브라우저 PoC endpoint 자체를 정식 운영 수준으로 인증한 것은 아니다. 브라우저 PoC를 실제 운영으로 승격할 경우 사용자 인증·권한·요청량 제한을 별도 구현해야 한다.

## 공개/보호 Gateway endpoint

공개:
- `GET /health`
- `GET|POST /v1/twiml`
- `WSS /v1/media` — `X-Twilio-Signature` 검증 필수

보호:
- `GET /v1/sessions`
- `POST /v1/tts`
- `POST /v1/clear`

보호 endpoint에는 `Authorization: Bearer <GATEWAY_CONTROL_TOKEN>` 또는 `x-gateway-control-token`을 사용한다.

## 별도 Gateway 배포 요구사항

- Node.js 20+
- persistent WebSocket 지원
- HTTPS/WSS 공개 URL
- TCP 443 외부 접근 가능
- Root Directory: `gateway`
- Start: `npm start`
- Health check: `GET /health`

Vercel Serverless Functions에는 장시간 Media WebSocket을 배포하지 않는다.

## 배포 후 사전점검

1. Vercel Preview production build 성공
2. Vercel 배포가 Hobby 12 Function 제한 안에서 성공
3. Vercel에 `STT_INTERNAL_API_TOKEN` 설정
4. Railway Gateway에도 동일한 `STT_INTERNAL_API_TOKEN` 설정
5. `GET /health`: `version=v0.15.0`, `liveE2E.enabled=true`, `liveE2E.internalApiTokenConfigured=true`, `liveE2E.readiness.ready=true`
6. 잘못된 internal token으로 `POST /api/telephony-adapter`의 `gatewayOperation`이 401인지 확인
7. 올바른 internal token으로만 Gateway operation이 통과하는지 확인
8. Gateway control endpoint도 무토큰 차단/정상 token 허용 확인
9. `GET /v1/twiml`이 동일 WSS URL 반환 확인

## E2E 시험 문장

실제 이름, 주민등록번호, 전화번호, 사건번호 등은 말하지 않는다.

첫 질문: `개인정보가 포함된 실제 민원 원문을 입력해도 되나요?`
- CLOVA STT
- approved fixture 근거 검색
- AI 답변
- Server TTS 수화기 재생

후속 질문: `그럼 주민등록번호가 들어간 내용도 입력하면 안 되나요?`
- 이전 대화 문맥 활용
- 승인근거 답변
- 자동 음성응답

새 주제: `회사에서 이직사유를 권고사직으로 정정할 수 있나요?`
- 승인근거 부족
- 담당자 확인 필요 음성 안내
- 자동 loop 중지

## 실전화 관찰값

보호된 `GET /v1/sessions`에서는 `sessionId`, inbound/outbound frame 수, turn 수, processing/speaking/stopped, STT chunk 수·완료상태, startedAt/lastSeenAt만 운영검증에 사용한다. callId/provider call ID는 통신 장애 추적 외에는 외부 문서나 캡처에 남기지 않는다.

통화 종료 후 합성 시험 STT session이 `completed`이고 transcript chunk index가 연속인지 확인한다.

- Twilio 실제 Media Stream 미연결
- 실제 전화 inbound audio 미수신

- fallback 미확인
