## 2. 추진 배경과 목적
### 2.1 현행 업무의 문제
- 전화 민원 청취 후 수기 정리 부담
- 민원요지 정리의 개인 편차
- 민원 분류와 후속 검토의 반복 업무

### 2.2 PoC 목표
1. 음성을 텍스트로 안정적으로 전사할 수 있는가
2. AI가 민원요지를 업무에 활용 가능한 수준으로 정제할 수 있는가
3. 담당자가 AI 결과를 빠르게 검토·수정·확정할 수 있는가
4. 업무영역·쟁점 자동분류의 참고 가치가 있는가
5. 오류와 변경 이력을 추적 가능한 구조로 남길 수 있는가

## 3. 개발 경과 및 버전 기준선
### 3.1 주요 버전
- `v0.4.1-stt-clova-async-callback`: CLOVA 비동기 callback 안정화
- `v0.5.0-stt-quality-evaluation`: 담당자 품질평가·재평가 upsert
- `v0.6.0-stt-classification-dashboard`: 자동분류·품질 대시보드
- `v0.7.0-stt-classification-review`: 담당자 분류 확정·정정·정확도·감사이력

### 3.2 주요 기술 구성
- Frontend: React / TypeScript / Vite
- Hosting/API: Vercel
- Database/Auth: Supabase
- STT: NAVER CLOVA Speech
- AI 정제/분류: OpenAI Responses API

## 4. 시스템 아키텍처
### 4.1 처리 흐름
음성 입력 → STT job → CLOVA async callback → transcript 저장 → AI 민원요지 정제 → 담당자 수정·확정 → 품질평가 → AI 민원분류 → 담당자 분류 확정·정정 → 대시보드 집계

### 4.2 안전장치
- 자동 처분·자격판단 없음
- 담당자 최종확정 원칙
- service-role 서버 경로 제한
- RLS 적용
- callback 인증 및 provider token 검증
- 변경·검토 감사이력 저장
